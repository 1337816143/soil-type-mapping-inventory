# 国家抽查材料挂载约定

国家抽查是现有导航末尾的独立专栏。内部按现站八个专题排列，区县仅作为材料归属和筛选项；不接入原成果收缴统计、管理员上传及答复流程。

## 当前材料与查看方式

`data/national-inspection.json` 记录已挂载的实际文件及关系。“区县 × 成果类型”为默认第一视图；“按专题检索”保留原查看方式。交叉表行列数字按物理路径去重，合并质控与评分文件仅计一次；空入口仅灰显禁用。浮层提供同批次新版在前的文件列表；浮层和专题文件列表均提供独立的预览与下载操作。不得为占位创建批次、假文件或链接，也不得从原质控区自动复制材料。读取失败须显示错误，而非当作空清单。

## 后续增量挂载

仅接到明确的真实材料后，保存文件至 `national-inspection-files/` 下，保留原文件名及历史批次，再向 JSON 清单增量加入记录。先确认所有文件真实存在且已在约定公开范围内，再发布清单。不要覆盖旧批次材料或复用其 ID 指代另一材料。

- `schemaVersion` 固定为 `1`。
- `batches` 每项包含稳定且唯一的 `id` 与界面显示用 `label`。仅在已有材料关联时创建，不按专题或区县猜造批次。
- `materials` 每项包含 `id`、`topicId`、`countyId`、`cityId`、`materialType`、`batchId`、`path`、`name`。
- `id` 为永久材料关系 ID。单份物理文件明确关联多个区县/专题时可有多个关系 ID，但共用同一个 `path`，批量下载按路径去重。
- `topicId` 顺序固定：`soilType`、`soilAttr`、`farmland`、`degradation`、`specialty`、`agriSuitability`、`landUse`、`reports`，名称完全沿用现站。
- `countyId` / `cityId`：`jinzhou` / `shijiazhuang`（石家庄晋州）、`shexian` / `handan`（邯郸涉县）、`ningjin` / `xingtai`（邢台宁晋）、`bazhou` / `langfang`（廊坊霸州）。
- `materialType` 只能是 `quality`（质控材料）或 `scoring`（评分材料），不能根据“评分”等关键词隐式改变其他元数据。
- `batchId` 必须引用 `batches` 中已登记 ID，历史批次始终保留。
- 批次可用 `order` 指定有原件依据的排序值，数值较大者在前；未注明批次的标签不猜排到具体轮次。材料可用正整数 `version` 记录原件明确的v2、v3等版本；未标版本不伪造v1。同批次新版在前，版本不构成新批次。
- 仅评分关系可带 `score`（0–100的完整总分）及必填 `scoreEvidence`（原件页码/表格位置与总分依据）。不得从质控意见条数、章节小计或报告内容暂行分数反推完整评分。交叉表按既有批次及版本顺序取最新可用完整评分，按钮显示数值；没有完整评分则保留“评分”。未知批次保持未知，不用文件修改时间或补充目录名确定新旧。
- 三报告评分使用可选 `reportScores` 数组，只能挂在 `reports` 的评分关系中，不与聚合 `score` 共存。每项含 `reportId`（`overall`/`work`/`data`）、`value`（0–100）、`basis`（评分标准版本）、`scope`（`full`或`content`）及 `evidence`（原件位置）；同一报告与标准版本不得重复。选取最新已登记文件中的分报告评分，不跨文件拼凑分数。
- 晋州“三报告”最新v3原件中，总体报告88分（第1页），工作报告2026版74分（第22页）/2024版75分（第21页），数据报告81分仅为报告内容分（第9–10页）。在同一成果列内分别显示“总体88”“工作74/75”“数据81*”，表下注明工作版本次序和星号范围，不将这些分数合成一个总分。点击各项仍查看原评分文件，保留预览和独立下载。晋州资源评价保持原件折合总分79.4分，不把71.5分合计当总分。
- 交叉表宽度与页面顶部玻璃外框一致，按标题长度分配列宽；桌面端完整列名与操作保持单行。窄屏用带完整名称提示的单行短列名，手机采用两字列名和较大的按钮文字，不将标题自动折成竖排。字体与留白只调整国家抽查模块。
- 同一报告、同一批次、同一版本有PDF只挂PDF；只有Word则挂Word，不用其他批次或版本的PDF排除Word。批注版、内部说明与整理清单不进入公开目录。原件和旧版不覆盖。
- 国家抽查沿用原预览组件，固定版本依赖及许可证位于 `assets/national-inspection-preview/`，同站公开加载；其他栏目保留原CDN加载方式。升级依赖需另行核实，不能将本目录视为自动升级入口。
- `path` 必须是 `national-inspection-files/` 开头的真实仓库相对路径；不允许外链、绝对路径、反斜杠、路径穿越、URL 编码、查询参数或片段。`name` 必须与路径最后一段的原文件名一致。
- 支持 PDF、Word、Excel、PowerPoint、ZIP、TXT、CSV、PNG、JPEG、WebP。“预览文件”打开站内预览，格式无法直接渲染时仍进入文件页；旁边“下载文件”使用同站公开原件与原文件名直接下载。

## 验证

运行 `node scripts/test-national-inspection.js`，校验结构、筛选、多个真实批次、关联去重、安全路径、真实文件存在性、空态与加载契约。DOM 回归另运行 `node scripts/test-national-inspection-dom.js`。现有项目校验与预览、公开批量下载、手机弹窗回归不可删减。测试样例只存在测试内存，不进入发布清单。

发布必须同时包含模块、样式、清单和真实新增文件；部署工作流的 sparse checkout 及必需文件检查须覆盖该独立目录。不得借此引入新账号、凭据或后台权限。
